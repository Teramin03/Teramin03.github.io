WSL2 + CentOS Stream 10 導入 2026

0. この備忘録について

0.1. 目的

Windows上のWSL2にCentOS Stream 10を導入し、常用できる状態まで持っていくまでの記録である。 再構築する機会が生じた際に、同じ調査を繰り返さずに済ませることを目的とする。

CentOS StreamはMicrosoft Storeの一覧には並ばないが、 CentOSのAlternative Images SIGがWSL専用のイメージ(.wslファイル)を公式に配布している。 本稿はこの方法を主とする。

0.2. 前提としたもの

  • CPUの仮想化支援機能(Intel VT-x / AMD-V)が利用できること
  • 管理者権限でPowerShellを実行できること
  • Linuxの基本的なコマンド操作

0.3. 扱わなかったこと

  • WSL1。選ぶ理由が無いため、WSL2に限定した
  • Docker等のコンテナ実行環境。使用していない
  • Hyper-V上に仮想マシンを立てる方式

0.4. 表記について

  • PS> で始まる行はWindows PowerShell(管理者)への入力である
  • $ で始まる行はCentOS側のシェルへの入力を示す
  • <...> で囲んだ箇所は自分の値に置き換える
  • 各節末尾の枠は、実際に手元で実行して確認した内容の記録である

1. WSL2の仕組みと事前準備

1.1. WSL1とWSL2の相違

WSL1はLinuxのシステムコールをWindowsカーネルの呼び出しに変換する方式であった。 WSL2はこれを改め、仮想マシン上で本物のLinuxカーネルを動作させる方式となっている。

WSL1WSL2
方式システムコールの変換仮想マシン + Linuxカーネル
互換性低い。動作しないものがある高い
Linux側の性能低い高い
Windows側ファイルの読み書き速い遅い

本物のカーネルが動くということは、systemd やコンテナも動作するということである。

1.2. 仮想化支援機能(VT-x / AMD-V)の有効化

近年のコンピュータでは既定で有効になっていることが多いが、無効の場合はBIOS(UEFI)設定画面で有効にする。 入り方は機種により異なるが、起動時に Del または F2 の連打で入れる場合が多い。 項目名はIntel CPUで「Intel VT-x」、AMD CPUで「AMD-V」または「SVM Mode」である。

1.3. Windowsの機能の有効化

「Windowsの機能の有効化または無効化」にて次の2つを有効にし、再起動する。

  • Linux用Windowsサブシステム
  • 仮想マシン プラットフォーム

検索バー（コントロールパネルと入力） > コントロールパネル > プログラム > Windowsの機能の有効化または無効化

確認01

タスクマネージャーのCPUの項に「仮想化: 有効」と表示されることを確認した。

2. WSL本体の導入と更新

2.1. 先に更新しておく

古い wsl.exe のまま作業を進めると、既定がWSL1のままであったり、 後述の --install --from-file が使えなかったりする。 イメージを入れる前に更新を済ませる 

PS> wsl --update
PS> wsl --version

2.2. 主なコマンド

コマンド意味
wsl --list -v登録済みの一覧と、各々のWSLバージョン・状態
wsl -d <名前>指定したものを起動
wsl --set-default <名前>既定のディストリビューションを設定
wsl --shutdownWSL全体を停止する。
wsl --status既定のバージョン等の状態表示

確認02

wsl --update の後に wsl --version を実行し、 WSL本体・カーネル・WSLgの各バージョンが表示されることを確認した。

3. CentOS StreamのWSLイメージ

3.1. 公式イメージの存在

Microsoft StoreにはUbuntu, Debian等が並ぶが、 CentOS Streamは含まれない。

CentOSプロジェクトのAlternative Images SIGが、 Live ISO等と並んでWSL専用のイメージを配布している。 Stream 9 と Stream 10 の双方、x86_64 と aarch64 の双方が用意されている。

3.2. 入手先

最新版へのリンクは CentOS Alternative Images のページにある。

3.3. .wsl とは何か

.wsl は、WSLがディストリビューションを配布するための形式である。

Windows側でこの拡張子がWSLに関連付けられているため、 ダウンロードしてダブルクリックするだけで導入が完了する。

3.4. イメージに含まれるもの

必要なものは概ね揃っている。

分類主なもの
基本systemd, dnf, yum, rpm, bash, coreutils, util-linux, sed, findutils, tar
ユーザ管理sudo, passwd, shadow-utils, pam
運用procps-ng, hostname, iproute相当, openssh-server, curl(minimal)
その他python3, vim-minimal, tzdata, ca-certificates, wsl-setup

逆に、入っていないもので最初に気になったのは次である。5.2. で補う。

  • 日本語ロケール(英語の最小構成のみ入っている)

確認03

Alternative Imagesのページから x86_64 用の .wsl を取得した。 サイズは概ね1GB台であった。

4. 導入と初回起動

4.1. ダブルクリックによる導入

ブラウザのダウンロード一覧から「ファイルを開く」を押下するか、 エクスプローラでファイルをダブルクリックする。 Windowsが内容を取り込み、登録まで自動で済ませる。

この場合、登録名は既定の CentOSStream-10-Alt となる。

4.2. 初回起動

PS> wsl -d CentOSStream-10-Alt

初回のみ、ユーザ名を尋ねられる。 ここで入力した名前で一般ユーザが作られ、以後の起動ではそのユーザで始まる。 スタートメニューにも登録名の項目が追加されるため、そこからも起動できる。

作られたユーザにはパスワードが設定されておらず、sudoが無条件に通る。

手軽ではあるが、sudo rm -rf の類を確認なしで実行できてしまうということでもある。 気になるならパスワードを設定する(5.1 参照)。

4.3. まず更新する

$ sudo dnf -y update

イメージはビルド時点で固定されているため、多くの場合更新が溜まっている。 以降の作業のためにも、最初に済ませておく。

確認04

wsl --list -v の VERSION が 2 と表示されることを確認した。 初回起動でユーザ名を尋ねられ、入力後にそのユーザのプロンプトで始まった。

5. 初期設定の確認

イメージ側で概ね設定済みであるため、この節は「確認と微調整」が中心となる。

5.1. パスワードとsudo

4.2 の通り、初期状態ではパスワードが未設定であるため設定する。 

$ sudo passwd <ユーザ名>

5.2. 日本語環境

イメージには英語の最小構成しか入っていない。日本語表示が必要であれば言語パックを追加する。 

$ sudo dnf -y install langpacks-ja langpacks-en
$ sudo localectl set-locale LANG=ja_JP.UTF-8

英語ロケールも併せて入れておく。 日本語のみとした場合、思わぬ箇所で不具合が出ることがある。

5.3. タイムゾーン

$ sudo timedatectl set-timezone Asia/Tokyo
$ date

確認05

言語パックを導入して LANG=ja_JP.UTF-8 を設定し、 date の出力が日本語かつJSTとなることを確認した。

6. Visual Studio Codeとの連携

6.1. 設定

VS CodeはWindows側にインストールする。 Linux側には入れない。拡張機能「WSL」を追加すると連携が有効になる。 

$ mkdir -p ~/<作業ディレクトリ>
$ cd ~/<作業ディレクトリ>
$ code .

初回はサーバ側の構成要素がLinux側に自動で導入される。 以後、編集・ターミナル・デバッグの全てがVS Codeの画面内で完結する。 ターミナルは「ターミナル > 新しいターミナル」で開くと、 CentOS側のシェルがそのまま現れる。

確認06

Windows側にVS Codeと拡張機能「WSL」を導入し、 CentOS側で code . を実行してWSL接続の状態で開くことを確認した。

7. バックアップ・削除

7.1. 書き出し

環境全体を1つのtarに固められる。 これがそのままバックアップになる。 

PS> mkdir C:\wslbackup
PS> wsl --export CentOSStream-10-Alt C:\wslbackup\cs10.tar

危険な変更を試す前に書き出しておけば、失敗しても登録し直すだけで戻せる。

7.2. 削除

PS> wsl --list -v
PS> wsl --unregister CentOSStream-10-Alt

--unregister は仮想ディスクごと消去する。確認は求められない。 実行前に書き出しの有無を確認すること。 Windowsのアプリ一覧からのアンインストール作業は生じない。

確認07

wsl --export でtarを作成できた。 wsl --unregister で削除した。

8. 詰まった点と対処

8.1. sudoがパスワードを要求しない

不具合ではなく、イメージの仕様である(4.2 参照)。 気になる場合は passwd でパスワードを設定

8.2. 設定を変えたのに反映されない

環境変数は新しいシェルの起動時に読まれるため、再起動が必要

PS> wsl --shutdown
PS> wsl
